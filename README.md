# ELITE Accessories — إيليت أكسسوريز

متجر عربي RTL متجاوب، مبني بـ React وTypeScript وVite وTailwind CSS وReact Router وLucide. لا يوجد خادم مخصص، ولا حسابات للزبائن أو خدمات مدفوعة مطلوبة.

## التشغيل

يتطلب Node.js 22 أو أحدث (تم التحقق باستخدام Node 24).

```sh
npm ci
npm run dev
npm run build
npm run preview
```

### وضع العرض التجريبي

عند ترك متغيرات Supabase فارغة، يعمل الكتالوج بمنتجات وصور وأسعار تجريبية. السلة والمفضلة وتعديلات لوحة المعاينة تُحفظ في localStorage في المتصفح نفسه. لا توجد آراء زبائن افتراضية، ولا رقم واتساب مفترض، ولا تسجيل طلبات أو إحصاءات مبيعات وهمية.

لوحة المالك موجودة على `/elite-management-portal` ولا توجد روابط عامة لها. في الوضع التجريبي فقط، يفتح زر واضح لوحة **معاينة محلية غير محمية**. لا تستخدم وضع العرض لإدارة متجر فعلي. لإعادة بيانات العرض، احذف مفتاح `elite-demo-v1` من تخزين المتصفح (السلة في `elite-cart` والمفضلة في `elite-favorites`).

الشعار الكتابي مؤقت لأن ملف الشعار الأصلي لم يُرفق. يمكن استبداله من إعدادات المتجر.

## ربط متجر فعلي بـ Supabase المجاني

1. أنشئ مشروع Supabase وشغّل محتويات `supabase/001_store.sql` مرة واحدة في SQL Editor. ينشئ جداول المنتجات والأصناف وصور الواجهة والآراء والإعدادات وعضوية المالك وStorage خاصًا، مع RLS. لا تعِد تشغيل الملف فوق سياساته الموجودة؛ استخدم migration جديدة للتغييرات اللاحقة.
2. أنشئ مستخدم المالك من Authentication → Users في لوحة Supabase. عطّل التسجيل العام؛ لا توجد واجهة تسجيل زبائن. أنشئ كلمة مرور قوية وأبقِ حساب المالك خاصًا.
3. أضف UUID الخاص بالحساب إلى جدول المالكين من SQL Editor فقط:

```sql
insert into public.owners(user_id) values ('UUID-FROM-AUTH-USERS');
```

4. انسخ `.env.example` إلى `.env.local` وأضف رابط مشروعك والمفتاح العام anon/publishable:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

هذه قيم عميل عامة؛ الأمان يعتمد على RLS وليس إخفاء المفتاح. **لا تضف service_role أو كلمة مرور المالك إلى متغيرات Vite أو الكود أو إعدادات المتجر.** المتغيرات تُضمّن وقت البناء؛ أعد تشغيل Vite أو أعد البناء بعد تعديلها.

5. في بيئة شبكية مقيّدة اسمح بنطاق مشروعك `YOUR_PROJECT.supabase.co` للـ HTTPS والاتصال الآني. استعمل إعدادات البيئة المدعومة لإضافة النطاق؛ لا تُعطّل TLS.
6. افتح مسار لوحة المالك وسجّل الدخول. الحساب الموثق الذي ليس ضمن `owners` لا يملك صلاحية إدارة، حتى لو حاول الاتصال مباشرة بواجهة البيانات.
7. يبدأ المتجر الفعلي دون بيانات تجريبية تلقائية. أضف الأصناف ثم المنتجات وصور الواجهة والإعدادات. يوجد استيراد اختياري لمحتوى العرض من لوحة التحكم؛ استبدل الصور والأسعار والمواصفات قبل البيع. الصور المحلية التجريبية تُنشر مع ملفات الموقع.
8. أدخل رقم واتساب **دوليًا مع رمز البلد**، ورمز العملة ورسوم ومناطق التوصيل ومعلومات التواصل، ثم احفظ. اختبر رسالة فعلية إلى رقمك قبل الإطلاق.

### الصلاحيات والصور

- الزائر يقرأ الصفوف المنشورة فقط. حساب المالك وحده يقرأ المسودات ويكتب ويحذف المحتوى.
- عضوية المالك لا يمكن إنشاؤها أو تعديلها من تطبيق العميل.
- الصور في bucket خاص اسمه `store-media`. يُسمح للزائر بطلب رابط موقّع فقط لصورة مرجعية ضمن محتوى منشور؛ المالك يستطيع معاينة المسودات. مسارات الصور المحفوظة هي `storage://filename.webp`.
- الروابط الموقّعة صالحة لخمس دقائق؛ قد يبقى رابط سابق صالحًا حتى انتهاء هذه المدة بعد إخفاء المحتوى. لا ترفع أي بيانات شخصية قبل إخفائها والحصول على الإذن.
- رفع JPG/PNG/WEBP فقط، حتى 8MB للملف. التطبيق يحوّل الصور إلى WebP ويحدّ أطول ضلع إلى 1800px. يدعم ترتيب صور المنتج وتعيين الرئيسية عبر نقل الصورة إلى البداية، والاستبدال والإزالة والقص.
- إزالة صورة من المحتوى لا تحذف الملف من التخزين، لتجنّب كسر أي مرجع مشترك. يمكن للمالك تنظيف الملفات غير المستخدمة من لوحة Supabase؛ سياسات الحذف تمنع غير المالك.
- إعدادات المتجر بيانات عامة؛ لا تضع فيها أسرارًا أو معلومات غير مخصصة للنشر.
- Realtime يحدّث المحتوى بين المتصفحات عند تفعيله؛ يوجد أيضًا تحديث عند عودة التركيز إلى النافذة. الحفظ يحدّث واجهة المالك فورًا.

## الوظائف

- صور واجهة متعددة مع ترتيب، صور هاتف مستقلة، نص اختياري، موضع النص، أزرار وروابط، وتبديل تلقائي قابل للإيقاف والتحكم واللمس.
- بحث فوري بالأسماء والأوصاف والأصناف، يتجاهل التشكيل والتطويل وأشكال الألف والياء. فلاتر الصنف والسعر والتوفر والجديد والعروض والمفضلة، وترتيب الأحدث والسعر والاسم.
- صفحات منتج، معرض صور، ألوان ومقاسات، كمية، مخزون، أسعار وعروض ومنتجات مرتبطة.
- حقيبة محفوظة حسب المنتج واللون والمقاس، مع التحقق من مجموع مخزون المنتج عبر خياراته.
- نموذج توصيل يطلب الاسم والهاتف والمدينة والعنوان، مع معلم ورابط خرائط وملاحظات اختيارية.
- رسالة واتساب عربية مشفرة تتضمن مرجعًا والمنتجات والخيارات والكميات والأسعار والتوصيل وبيانات الزبونة. لا يعد التطبيق فتح واتساب تأكيد استلام؛ يجب الضغط على إرسال داخل واتساب. لا تُسجل الطلبات ولا يُحجز المخزون تلقائيًا؛ المالك يؤكد التوفر ويحدّث المخزون من اللوحة.
- إدارة كاملة للمنتجات والأصناف والبنرات والآراء والإعلان وترتيب وظهور أقسام الرئيسية وإعدادات المتجر. حفظ المسودات، معاينة، نسخ المنتجات، إخفاء ونشر وحذف مؤكد.
- الآراء صور يرفعها المالك فقط، مع تكبير وتنقل ولمس. لا توجد أسماء أو تقييمات مختلقة.

## التحقق

```sh
npm test               # اختبارات البحث والتسعير والخيارات والتحقق ورسالة واتساب
npm run build           # TypeScript وبناء الإنتاج
npm run dev             # في نافذة مستقلة قبل الاختبارات التالية
npm run test:e2e         # Playwright: متجر، بحث، سلة، طلب، إدارة، هاتف وRTL
```

ملف Playwright مضبوط على Chromium الموجود في `/usr/bin/chromium` في البيئة السحابية. في جهاز آخر ثبّت Chromium بـ `npx playwright install chromium` واحذف `executablePath` من الإعداد. تستخدم اختبارات المتصفح localStorage معزولًا ولا تُنشئ آراء أو طلبات في متجر فعلي.

للتحقق من الأمان في مشروع Supabase: جرّب قراءة مسودة ورفع/تعديل/حذف بيانات كزائر، ثم بحساب موثّق غير مالك؛ يجب رفضها. تحقق أن المالك يستطيع ذلك، وأن الزائر يستطيع قراءة المحتوى المنشور وتوقيع صوره فقط. هذه الفحوص الحية تتطلب مشروعًا ومفاتيح وحسابات اختبار، ولا يغني عنها نجاح بناء الواجهة.

## النشر المجاني

انشر `dist` على Cloudflare أو Vercel أو أي استضافة ملفات ثابتة مع SPA fallback. يتضمن المشروع `vercel.json` لدعم الروابط المباشرة على Vercel، بينما يعتمد Cloudflare على معالجة SPA الأصلية في `wrangler.jsonc`. أمر البناء `npm run build` ومجلد الإخراج `dist`. أضف متغيرات Vite قبل البناء واضبط Site URL/Redirect URLs في Supabase على نطاق الموقع الفعلي. لا تنشر ملف `.env.local`.

للنشر على Netlify فقط، أنشئ ملف `dist/_redirects` بعد اكتمال البناء بمحتوى `/* /index.html 200`. لا تضف هذه القاعدة إلى حزمة Cloudflare لأنها تسبب حلقة إعادة توجيه ويرفضها النشر.

لا يعتمد الموقع على خدمات خطوط أو صور خارجية وقت التشغيل؛ الصور والخطوط موجودة في `public`. الخط IBM Plex Sans Arabic برخصة OFL المرفقة في `public/fonts/OFL.txt`. صور العرض الأساسية مولّدة خصيصًا للمشروع ولا تمثل منتجات فعلية أو آراء عملاء. استبدلها بصور الكتالوج الحقيقي وشعار العلامة عند الإطلاق.


## النشر على Cloudflare Pages

لرفع النسخة الجاهزة يدويًا: افتح Cloudflare Dashboard ثم Workers & Pages → Create application → Pages → Upload assets (أو Drag and drop). اختر اسم المشروع، وارفع ملف ZIP الذي يحتوي على ملفات `dist` مباشرة في جذره، ثم اضغط Deploy. سيعرض Cloudflare رابط `pages.dev` بعد نجاح النشر.

لا ترفع مجلد الشيفرة أو `node_modules` أو ملفات `.env`. حزمة Cloudflare المعدّة في هذه الجلسة هي `/workspace/elite-cloudflare-pages.zip`، وتستثني ملف `_redirects` الخاص بالاستضافات الأخرى. تعتمد Pages على معالجة SPA الأصلية: لا تضف ملف `404.html` في الجذر، لتعمل الروابط المباشرة مثل `/shop` و`/product/p1` و`/elite-management-portal` دون إعادة توجيه ملفات JavaScript والصور إلى HTML.

عند اختيار ربط Git بدل الرفع اليدوي، يجب رفع الشيفرة إلى المستودع أولًا؛ أمر البناء `npm run build`، ومجلد الإخراج `dist`، ونسخة Node هي 24. ينظّف أمر البناء الافتراضي ملف `dist/_redirects` تلقائيًا؛ لا حاجة إلى خطوة يدوية إضافية. متغيرات `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` تُضبط قبل البناء؛ الرفع اليدوي لا يعيد بناء الملفات ولا يحقن متغيرات Vite بعد ذلك. بدونها يعمل الموقع في وضع العرض التجريبي. بعد ربط Supabase، أضف نطاق الموقع الجديد إلى إعدادات عناوين الموقع المسموحة في Supabase.


## النشر من GitHub إلى Cloudflare Workers

يتضمن المشروع `wrangler.jsonc` لنشر متجر ملفات ثابتة مع معالجة SPA الأصلية، دون خادم مخصص. اسم المشروع مضبوط على `eliteaccessories` ليطابق شاشة إعداد Cloudflare الحالية.

في شاشة Cloudflare المتصلة بمستودع GitHub الخاص اضبط:

| الحقل | القيمة |
| --- | --- |
| Project name | `eliteaccessories` |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Preview command | `npx wrangler versions upload` |
| Root directory | جذر المستودع |

يستخدم Cloudflare نسخة Wrangler المثبتة والمثبتة في lockfile. يزيل أمر البناء الافتراضي أي ملف `_redirects` متبقٍ من `dist`، وتعمل روابط React الداخلية عبر `not_found_handling: single-page-application`. يبقى `npm run build:cloudflare` اسمًا بديلًا للأمر نفسه. تم تفعيل `workers_dev` لتوفير رابط Cloudflare المجاني؛ لا ينشئ ذلك نطاقًا مخصصًا مدفوعًا.

للنشر من جهاز آخر بعد ربط حساب Cloudflare وتشغيل المصادقة المحلية:

```sh
npm ci
npm run deploy:cloudflare
```

لا تُضف رموز حساب Cloudflare أو مفاتيح الخدمة السرية إلى Git. لا يتطلب النشر من واجهة Cloudflare وضع رمز حسابك في كود المشروع. عند ربط Supabase اضبط متغيرات Vite في بيئة البناء قبل النشر، ثم حدّث عناوين الموقع في Supabase.

خصوصية مستودع GitHub وخصوصية رابط المتجر أمران منفصلان: المستودع الخاص يحجب ملفات المصدر عن غير المصرح لهم، لكن رابط المتجر المنشور يكون عامًا ما لم تفعّل Cloudflare Access. ملفات واجهة المتجر التي يرسلها المتصفح للزوار قابلة للعرض كأي موقع ويب، لذلك لا تحتوي على أسرار.


## تشخيص تسجيل دخول المالك

رسالة تسجيل الدخول تميّز بين البريد غير المؤكّد، وبيانات الدخول المرفوضة، وفشل الاتصال، ومفتاح API غير الصحيح، وغياب عضوية المالك، وفشل قراءة جدول الصلاحيات. لا يُسمح لحساب موثّق بدخول الإدارة ما لم تُثبت عضويته في `owners`.

في صفحة الدخول يمكن فتح «تفاصيل الاتصال» لمقارنة اسم مضيف مشروع Supabase بمشروع لوحة التحكم. يعرض هذا المضيف فقط؛ لا يعرض المفاتيح أو كلمات المرور. زر العين يسمح للمالك بالتحقق من كتابة كلمة المرور على جهازه.

شغّل `supabase/check_owner.sql` في SQL Editor للتشخيص عند الحاجة: يعرض أحدث خمسة حسابات مع حالة تأكيد البريد ووجود كلمة مرور وعضوية المالك، دون قراءة أو عرض قيمة كلمة المرور أو تجزئتها. لا يغيّر أي حساب أو صلاحية. لا تنشئ مستخدمًا جديدًا لمجرّد ظهور خطأ اتصال أو إعداد.

```sh
npm test       # اختبارات منطق المتجر والمصادقة وصلاحية المالك
npm run test:auth  # متصفح مع Supabase مُحاكى؛ يشغّل خادم اختبار منفصلًا تلقائيًا
```

اختبارات المصادقة تستخدم عنوان `.invalid` ومفتاح اختبار واستجابات HTTP محاكاة؛ لا تتصل بمشروع Supabase فعلي ولا تتحقق من كلمة مرور حساب حقيقي.

يعتمد اختبار المصادقة في المتصفح على نسخة إنتاج مبنية بمضيف اختبار محاكى ومعزولة في `/tmp`، وليس بيانات المشروع الحقيقية. تُصحَّح روابط `*.supabase.co` إلى عنوان المشروع الأساسي حتى عند نسخ مسار REST أو Auth بالخطأ. الأخطاء غير المعروفة تُظهر حالة HTTP ونوع الخطأ فقط، دون عرض استجابة المزوّد الخام أو بيانات الدخول.


## التوصيل حسب المنطقة

الأسعار الافتراضية: القدس 30 شيكل، الضفة الغربية 20 شيكل، والداخل 70 شيكل. يختار الزبون المنطقة من ملخص الحقيبة أو الطلب. يظهر مجموع المنتجات قبل التوصيل حتى يختار منطقة، ثم تُضاف رسوم المنطقة إلى الإجمالي، وتظهر المنطقة والرسوم والإجمالي نفسه في رسالة واتساب.

اختيار المنطقة مطلوب قبل إرسال الطلب، ويُحفظ وحده في المتصفح لتستمر المنطقة المختارة بين الحقيبة وإتمام الطلب. لا تُحفظ بيانات اسم الزبون أو عنوانه في localStorage. تُحسب الرسوم من إعدادات المتجر، ولا يقبل مولّد الرسالة مبلغ توصيل يرسله نموذج الزبون.

يمكن تعديل أسعار المناطق الثلاث من إعدادات المتجر في الأدمن. تُحفظ في `settings.payload.deliveryRates`، وتستخدم السجلات القديمة التي لا تحتوي هذا الحقل الأسعار الافتراضية أعلاه؛ لا يلزم تشغيل migration جديدة أو تغيير سياسات الصلاحيات. يبقى الحقل القديم `deliveryFee` للتوافق مع البيانات السابقة، ولا يُستخدم لحساب الطلبات الجديدة.

## صور المنتجات في طلب واتساب

يضيف إرسال الطلب رابط الصورة الرئيسية ورابط صفحة المنتج لكل منتج مختلف في السلة. لا تُكرر الصور بسبب زيادة الكمية أو اختيار لون آخر للمنتج نفسه. تُحوَّل صور الموقع النسبية إلى روابط كاملة على النطاق الحالي، ولا تُرسل قيم `data:` أو `blob:` أو `storage://` كنصوص صور.

صور Supabase تبقى في التخزين الخاص وتُنشأ لها روابط موقّعة صالحة لسبعة أيام من تجهيز الطلب، وفق سياسات قراءة المنتجات المنشورة الحالية، مع رابط صفحة منتج ثابت عند انتهاء رابط الصورة. لا يلزم تغيير bucket أو RLS أو تشغيل SQL إضافي. إذا تعذّر إنشاء رابط صورة يبقى رابط المنتج داخل الطلب.

بعد تجهيز رسالة الطلب يظهر قسم صور المنتجات. على الأجهزة الداعمة لـ Web Share API يمكن اختيار «مشاركة الطلب مع الصور» ثم WhatsApp ومحادثة المتجر. يُرسل الموقع ملفات JPEG مُعدّة مسبقًا مع نص الطلب إلى قائمة المشاركة؛ دعم النص مع عدة صور يختلف حسب النظام والتطبيق، لذلك تبقى رسالة الطلب الأساسية متاحة من رابط واتساب. لكل صورة زر تنزيل مستقل، لتتمكن الزبونة من إرفاقها يدويًا في المتصفحات غير الداعمة للمشاركة.

رابط `wa.me?text=` يملأ نص رسالة فقط، ولا يرفق ملفات صور تلقائيًا ولا يثبت استلام المتجر للطلب. المستخدم يختار المحادثة ويضغط إرسال داخل واتساب. لا يستخدم هذا الحل WhatsApp Business API أو خدمة مدفوعة، ولا يرسل الموقع رسائل في الخلفية.

## تنظيف السلات عند حذف أو إخفاء منتج

تُزال كل خيارات المنتج المحذوف أو المخفي من السلة المحفوظة عند استلام نسخة ناجحة من الكتالوج، ويتحدث العدد والإجمالي ورسالة الطلب. لا يمسح التحميل الأولي أو فشل الاتصال السلة. المنتج المنشور الذي نفد مخزونه يبقى خاضعًا لفحص المخزون المعتاد.

تصل التحديثات عبر Realtime عند توفره، مع تحقق احتياطي كل 15 ثانية أثناء ظهور الصفحة، وعند العودة إليها أو عودة الاتصال. هذا التحقق ضروري لأن إخفاء المنتج قد يمنع وصول حدث Realtime للزائر بسبب RLS. المستخدم غير المتصل تُنظَّف سلته عند عودته وتحميل الكتالوج بنجاح؛ لا يمكن تعديل تخزين متصفح غير متصل عن بُعد. تتزامن السلة وتعديلات العرض التجريبي كذلك بين تبويبات المتصفح نفسه.

## العربية والعبرية

تظل العربية اللغة الافتراضية. يتيح محدد اللغة في رأس الموقع اختيار `עברית`، ويحفظ الاختيار في `elite-language`. صفحات المتجر والبحث والتصفية والمنتج والسلة وإتمام الطلب والمعلومات ورسالة واتساب تدعم العبرية واتجاه RTL. لا يتغير رابط الصفحة أو معرّف المنتج أو المخزون أو سعره عند التبديل، وتبقى قيم الألوان والمقاسات في السلة ثابتة بينما تُترجم تسمياتها المعروضة.

يضيف الأدمن، الذي يبقى بالعربية، قسم «المحتوى بالعبرية» للمنتجات والأصناف وصور الواجهة وتعليقات الآراء وإعدادات المتجر والرئيسية. تُحفظ النصوص في `payload.translations.he` ضمن المستند نفسه، دون جداول أو SQL أو سياسات صلاحيات جديدة. الصور والأسعار ورسوم التوصيل مشتركة بين اللغتين. حقول الألوان والمقاسات العبرية تقابل الخيارات الأصلية بالترتيب.

تُترجم الواجهة والمحتوى التجريبي المضمّن. المحتوى الخاص الذي أضافه المالك يحتاج تعبئة ترجمته العبرية من الأدمن؛ الحقول التي تُترك فارغة تعرض الأصل العربي بدل إخفاء المنتج أو تغيير بياناته. لا يستخدم المتجر خدمة ترجمة خارجية ولا يرسل بيانات المنتجات إليها.
